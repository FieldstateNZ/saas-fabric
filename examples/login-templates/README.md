# Login template packages

Brand assets and page templates are separately versioned OCI artifacts. The
`welcome-panel` example overrides Keycloak's `footer.ftl` with an actual FreeMarker
macro, localized copy and a two-column layout. The built-in sign-in form and its
authentication behavior remain inherited. The blue client keeps the standard
layout; the copper client selects this package independently of its brand.

Publish through ORAS, independently of Aspire:

```sh
./examples/login-templates/publish.sh localhost:REGISTRY_PORT --plain-http
```

The package digest is deterministic for unchanged files. The platform operator
adds the full digest-pinned reference to `approved_login_templates` when calling
the OpenTofu module. The demo's policy is in
`infrastructure/opentofu/demo-template-policy.json`; it is separate from client
YAML. The client then selects:

```yaml
loginTemplate:
  artifact: registry.example/login-templates/welcome-panel@sha256:DIGEST
  # plainHttp: true # local registry only
```

A brand selection is required. Unsetting `loginTemplate` restores the inherited
layout and retains the brand. Changing either digest creates a new composed theme
name. OpenTofu installs all files first, then selects the realm theme. Previous
versions are retained for rollback.

The artifact type is `application/vnd.saas-fabric.login-template.v1`. It contains
`template.json` plus the exact files declared in its `files` object. Every file is
an individual OCI layer, with its path in `org.opencontainers.image.title`.
The manifest declares schema version 1, a name, parent `keycloak`, and the tested
Keycloak major.minor line (`26.6` in this example). Module `keycloak_version` must
match this declaration; it must also match the actual deployment target.

Supported overrides:

- `login/*.ftl`: shared layout, individual forms, footer and partial templates.
- `login/resources/css/*.css`: layout styles, appended after platform brand CSS.
- `login/messages/messages_<locale>.properties`: localized text.

`theme.properties` is generated by the module. Archives, path traversal, duplicate
layers, undeclared files, JavaScript files and overrides of `brand.css` are rejected.
Files are UTF-8; each layer is limited to 2 MiB and each package to 16 MiB/32 layers.
This allowlist is a deployment trust boundary, **not a FreeMarker sandbox**.
Templates are server-executed trusted code and approved CSS can change page behavior.
The platform must review packages and run compatibility tests before approval.
Digest checks prove content integrity; they do not prove publisher identity.
Do not add arbitrary tenant-uploaded template digests to the approved list.

For bespoke forms, preserve Keycloak's form action, field names, error messages,
authentication methods and required hidden inputs. Prefer small inherited overrides
over copying whole upstream pages. Test every enabled flow before deployment:
login, validation errors, registration/reset if enabled, MFA/passkeys/federation
if enabled, language selection, mobile layout, and keyboard accessibility.
The demo tests page rendering, inherited fields/action, invalid-login feedback,
client isolation, responsive layout and artifact admission. It does not enable or
claim compatibility testing of registration, MFA, passkeys or federation.

Template source and message files stay outside the public brand directory.
Public brand manifests and logos remain reusable by other applications.
On a fresh demo registry, publish both the brand fixtures and this package before
restarting failed client applies. Publishing/approval are separate from client
reconciliation; the deployment never silently trusts a newly uploaded template.

Run the committed end-to-end checks against the allocated gateway URL:

```sh
python3 examples/brands/verify.py http://localhost:GATEWAY_PORT
python3 examples/login-templates/verify.py http://localhost:GATEWAY_PORT
python3 -m unittest discover -s infrastructure/opentofu/tests -v
```

The script checks rendered forms without submitting them. Browser QA separately
verified invalid-login feedback using nonexistent fixture credentials; no account
was created or signed into.
